# QRコードスキャナー風UI仕様書(Web版)

対象:iOS標準QRコードスキャナー(コントロールセンターから起動するタイプ)の挙動をWeb UIとして再現するための仕様書。
※本書は仕様定義のみを目的とし、実装方法(技術選定・コーディング)には言及しない。

参照元:実機録画GIF(320×692px、47フレーム、100ms/フレーム、全体4.7秒)の解析結果に基づく。

---

## 1. 全体構成

### 1.1 画面(ビュー)一覧

| ID  | 画面名               | 概要                                                       |
| --- | -------------------- | ---------------------------------------------------------- |
| V0  | カメラプレビュー画面 | スキャン待機〜検出〜確定までを表示する単一画面             |
| V1  | 結果アクションシート | V0の上にオーバーレイ表示される、読み取り結果のボトムシート |

本UIは画面遷移(ページ遷移)を伴わず、単一画面上でレイヤーの表示/非表示・変形のみで完結する。

### 1.2 レイヤー構造(Z軸、下から上)

| Z順        | レイヤー名                   | 内容                                     | 常時表示か                           |
| ---------- | ---------------------------- | ---------------------------------------- | ------------------------------------ |
| L1(最背面) | カメラ映像レイヤー           | 背面カメラのライブ映像                   | 常時(ただしL4表示中は上から覆われる) |
| L2         | 検出コードの固定画像レイヤー | コード確定後にキャプチャした静止画を合成 | 状態C(確定後)以降のみ                |
| L3         | スキャンガイド枠レイヤー     | 4隅のL字コーナーマーク                   | 状態Bのみ非表示になる瞬間を除き常時  |
| L4         | 案内バナーレイヤー           | 画面上部のテキストピル                   | 状態限定                             |
| L5         | 操作ボタンレイヤー           | 懐中電灯ボタン等                         | 常時                                 |
| L6(最前面) | 結果アクションシート         | 読み取り結果を表示するボトムシート       | 状態E以降のみ                        |

**重要仕様(実機で確認された挙動)**:
コード確定(状態B→C)のタイミングで、コード領域のみを静止画としてキャプチャし、以降はそのキャプチャ画像を固定位置に合成表示する。背後のライブカメラ映像(L1)はそのまま動き続けるため、ユーザーがカメラを動かす(スマホを下ろす等)と、コード以外の領域はぼける一方、コード自体は確定時の鮮明な状態を保ち続ける。これは実機の鮮鋭度測定(下記6.3参照)で確認済みの仕様であり、本UIでも再現対象とする。

## 2. 状態遷移(ステートマシン)

```
[A] 待機(コード探索中)
     │  コードが視野に入らない/検出できない間、継続
     ▼
[A'] 案内表示(探索中のサブ状態)
     │  A開始から一定時間経過で自動遷移(案内バナー表示)
     │  コードのパターンを検出
     ▼
[B] 検出・ロックオン
     │  ガイド枠がコードのバウンディングボックスへスナップ
     │  コードの傾き・移動に追従(トラッキング)
     │  トラッキングが一定時間安定
     ▼
[C] 認識確定
     │  ガイド枠が一瞬非表示になる(確定の合図)
     │  コード領域を静止画としてキャプチャ、固定レイヤーに切替
     │  カメラがわずかに引く(ズームアウト相当の見た目)
     ▼
[D] 確定後トラッキング表示
     │  タイトなガイド枠がコード領域のみを囲んで再表示
     │  一定時間(または即時)後、結果シートの表示処理へ
     ▼
[E] 結果表示
     │  画面下端から結果アクションシートがスライドイン
     │  シート確定表示で状態停止(ユーザー操作待ち)
```

状態Aへ戻る条件:結果シートで「キャンセル」等が選択された場合(本GIFには含まれないが、通常UIとして必要)。

## 3. コンポーネント仕様

### 3.1 スキャンガイド枠(L3)

| 項目              | 仕様                                                                                                                                                            |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 形状              | 直角L字、4隅独立(枠の辺は描画しない)                                                                                                                            |
| 角の丸み          | あり(角丸半径:短辺の約15〜20%目安)                                                                                                                              |
| 色                | 白、不透明に近い(半透明ではあるが視認上ほぼ白)                                                                                                                  |
| 線の太さ          | 状態を通じて一定(検出前後で太さの変化なし)                                                                                                                      |
| サイズ(状態A/A')  | 画面幅の約60%角の正方形(画面中央配置)                                                                                                                           |
| サイズ(状態B以降) | 検出したコードのバウンディングボックスに一致するサイズ(コードにより可変)                                                                                        |
| 位置・回転        | 状態B以降、検出コードの傾き(パース変形)に追従して回転・台形変形する                                                                                             |
| 状態Aでの動き     | 静止(アイドルアニメーションは確認されず)                                                                                                                        |
| 状態B遷移時の挙動 | フルサイズ→コードサイズへの変化は**1〜2フレーム(約100〜200ms)以内に完了**。緩やかな縮小ではなく、瞬時のスナップに近い                                           |
| 状態Cでの挙動     | 一瞬(1フレーム、約100ms相当)完全非表示になる                                                                                                                    |
| 状態Dでの挙動     | 再表示。ただしこの時は**コード本体のみを囲む、より小さくタイトな枠**になる(状態Bより小さい可能性がある。実機ではバーコード部分を含まず、QR部分のみを囲んでいた) |

### 3.2 案内バナー(L4)

| 項目               | 仕様                                                                                                          |
| ------------------ | ------------------------------------------------------------------------------------------------------------- |
| 形状               | 角丸ピル型(角丸半径大)                                                                                        |
| 背景               | 黒、半透明(すりガラス調でも可)                                                                                |
| 文字色             | 白                                                                                                            |
| 文言               | 「スキャンするコードを見つけてください。」(検出対象未確定時)                                                  |
| 表示位置           | 画面上部中央、セーフエリア直下                                                                                |
| 出現タイミング     | 状態A開始から約0.7秒後(実機値、要調整可)                                                                      |
| 出現アニメーション | フェードイン。実測ではフレーム間(100ms未満)で切り替わっており、クロスフェードの中間状態が視認できないほど高速 |
| 消滅タイミング     | 状態Bで検出・追従が安定した時点(実機では検出から約0.5秒後)                                                    |
| 消滅アニメーション | フェードアウト。出現と同様、100ms未満の高速な切り替え                                                         |

### 3.3 操作ボタン(L5)

| 項目           | 仕様                                                                                                                                                           |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 種類           | 懐中電灯(トーチ)アイコンボタン                                                                                                                                 |
| 形状           | 円形、半透明の暗色背景                                                                                                                                         |
| 位置           | 画面下部中央                                                                                                                                                   |
| 状態による変化 | 状態D以降、下部に別の操作ラベル(例:「コード表示」等)が追加で並ぶ場合がある(実機ではメルペイ側UIの影響であり、本仕様のスキャナー標準UIとしては必須要件としない) |

### 3.4 結果アクションシート(L6)

| 項目                 | 仕様                                                                                                                                                                                                                                    |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 表示トリガー         | 状態D→Eへの遷移(確定後トラッキングから一定時間、または即時)                                                                                                                                                                             |
| スライド方向         | 画面下端から上方向                                                                                                                                                                                                                      |
| 背景                 | 暗色半透明(すりガラス調、下のレイヤーが透けて見える)                                                                                                                                                                                    |
| 上端の形状           | 角丸(左右上のみ)                                                                                                                                                                                                                        |
| 内部構成(上から順)   | ①種別アイコン+ラベル(例:「テキスト」) ②本文(読み取り結果の文字列、複数行対応、等幅フォント推奨) ③候補アクションボタン(縦積み、青文字リンク調、例:「Webを検索」「コピー」) ④キャンセルボタン(シート最下部、独立した見た目・余白で区切る) |
| スライドイン所要時間 | 実測 約100〜200ms(1〜2フレーム)                                                                                                                                                                                                         |
| イージング           | 実機フレームレートでは判別不能。**推測だが**、標準的なUIのeaseOut系(減速)が妥当                                                                                                                                                         |
| 完了後の状態         | 静止。背後のL1(カメラ映像)・L2(固定QR画像)・L3(ガイド枠)は表示され続けるが、シートに大部分が隠れる                                                                                                                                      |

## 4. タイミング仕様(基準値)

実機解析(100ms単位サンプリング)から抽出した基準値。Web実装時の初期値として使用を想定。

| フェーズ                            | 目安時間                   | 備考                                 |
| ----------------------------------- | -------------------------- | ------------------------------------ |
| 状態A(バナーなし)                   | 〜0.7秒                    | コード非検出時は継続                 |
| 状態A'(バナー表示中、コード探索)    | 可変(コードが見つかるまで) | 実機では約1.2秒観測                  |
| バナー フェードイン/アウト          | 各100ms未満                | ほぼ瞬時                             |
| 状態B(検出→スナップ)                | 100〜200ms                 | ガイド枠のサイズ変化                 |
| 状態B(トラッキング安定〜バナー消滅) | 約400〜500ms               | コード検出からの経過時間             |
| 状態C(枠非表示=確定演出)            | 約100ms                    | 1フレーム相当                        |
| 状態D(確定後トラッキング表示)       | 約300〜400ms               | シート表示前の間                     |
| 状態E(シートスライドイン)           | 100〜200ms                 |                                      |
| **合計(検出開始〜結果確定)**        | **約1.6〜1.8秒**           | バナー表示開始から結果シート静止まで |

## 6. 特記事項・設計上の判断ポイント

### 6.1 「確定後の固定画像合成」について

実機では、コード確定(状態C)以降、コード部分だけが鮮明さを保ち、周囲(同一被写体面上の他要素・背景)は自然にボケていく現象が観測された。これは以下のいずれかの実装意図によるものと推測される。

1. **ユーザー体験上の理由**:結果確定後にユーザーが手を下ろし始めても、「読み取れたコード」自体は視覚的に明瞭なまま保持することで、成功体験を損なわない
2. **技術的な理由**:認識処理で使用した高解像度の静止フレームをそのまま流用し、以降はカメラのプレビュー更新負荷を下げている可能性

Web版UIとしては、**状態C以降、検出領域を「その瞬間のスナップショット画像」として固定合成する**仕様を採用することを推奨する(6.3の測定データが根拠)。

### 6.2 案内バナーの表示条件

実機では「一定時間コードが見つからない場合にバナーが表示される」という条件を採用しているとみられる(起動直後はバナーなし)。Web版でも、起動直後の一定時間はバナーを出さず、探索が長引く場合にのみ表示する設計を踏襲することを推奨する。

### 6.3 実測データ(鮮鋭度比較、根拠資料)

| フレーム(状態)    | コード領域                 | 同一平面上の非コード領域   | 画面外背景                 |
| ----------------- | -------------------------- | -------------------------- | -------------------------- |
| 状態B中(確定前)   | 402.7〜1148.2              | 151.7〜985.6(コードと連動) | 39.7〜76.1                 |
| 状態D以降(確定後) | 160.9〜479.1(安定して高い) | 33.8〜44.4(急落)           | 15.1〜50.2(同水準まで低下) |

確定前は「コード領域」と「同一平面上の非コード領域」の鮮鋭度が連動して増減するのに対し、確定後はコード領域だけが高い値を維持し、非コード領域は画面外背景と同水準まで落ちる。この非対称性が、6.1の固定画像合成仕様の根拠である。

## 7. 未確定・要検討事項

- イージング関数の具体的な種類・カーブ(実機の100msサンプリングでは特定不可。デザイン側で任意に決定可)
- バナー出現までの待機時間の正確な閾値(実機は起動から約0.7秒だが、コード探索状況に応じた動的な閾値である可能性)
- 状態Dの所要時間が固定値か、何らかの安定条件(トラッキングの揺れが一定以下になる等)によって可変か
- 結果シートの「キャンセル」操作後、状態Aに戻る際のアニメーション(本GIFに含まれず未検証)
- 複数コードが同時に視野内にある場合の挙動(未検証)
- エラー時(コード認識失敗・非対応フォーマット等)の表示仕様(未検証)
